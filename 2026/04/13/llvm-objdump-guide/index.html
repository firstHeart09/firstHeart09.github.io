llvm-objdump工具使用说明

发表于2026-04-13|更新于2026-10-05|工具说明
|浏览量:

在日常的工具中，我们经常需要看程序的汇编代码，但是一般情况下，程序给我们提供的只是可执行文件或者目标文件，这类文件如果想要直接打开看其内容，是不现实的。所以，我们此时需要一些工具，去将这个文件翻译成我们能够读懂的语言，这就是 llvm-objdump 的具体使用场景。

针对以上测试代码，使用clang++ hello.cc命令进行编译链接，生成最终的可执行文件。

llvm-objdump 常用命令详解

这个命令可以用于查看和分析目标文件、可执行文件、库文件的工具，如objdump命令一样。这个命令可以用于查看以下信息：

  • 反汇编机器指令，查看二进制代码对应的汇编内容；
  • 查看各节区的原始内容
  • …

反汇编相关

-d / –disassemble 只反汇编可执行节区中的代码

通过上述参数选项，可以看到 .text sections 反汇编代码。

-D / –disassemble-all 反汇编文件中的所有节区

非代码节区也会被尝试解码，输出不一定是有意义的指令。

非代码节区也会被尝试解码，输出不一定是有意义的指令。

–disassemble-symbols= 只反汇编文件中 value 指定的函数，得到对应的反汇编代码

在实际使用中，可以使用-S/--source参数将源码与汇编代码交叉显示；使用--line-numbers/-l参数可以在反汇编的时候显示源码行号信息。

显示节区内容

在这部分，可以通过参数显示文件的节区内容，以十六进制的方式显示

-s / –full-contents 显示节区的完整内容

–section= / -j 只操作指定的节区内容即只关注某个节区

调试信息相关

--dwarf=<value>

转储指定的 DWARF 调试节区，目前帮助信息中显示支持 frames。

--unwind-info / -u

显示栈展开信息（unwind information）。

这些选项常用于异常处理、调用栈恢复、调试器支持和底层 ABI 分析。

main函数反汇编

可以看到，在汇编代码的一开始，首先将栈的信息保存(建立栈帧)，这部分主要是为了后续退出这个函数的时候，好恢复原有的信息。

然后进行的是局部变量初始化

链接前后的函数调用

入职准备篇使用的 test.cc 包含 add 和 main 两个函数。下面摘录同一次实验中 main 调用 add 的指令，其他节区输出省略：

目标文件中的四字节位移尚未填写，所以反汇编暂时显示下一条指令地址 0x3e；这不是最终的调用目标。重定位记录要求链接器从 0x3a 开始写入位移。

本例链接后直接调用 add，目标地址是 0x1740，下一条指令地址是 0x177e，因此位移为 0x1740 - 0x177e = -0x3e。对应的 32 位补码为 0xffffffc2，小端编码就是 c2 ff ff ff。如果调用经过 PLT，目标则需要按 PLT 入口计算，不能一律当作函数本体地址。
