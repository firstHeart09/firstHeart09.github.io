llvm-readelf工具使用说明

发表于2026-04-16|更新于2026-10-05|工具说明
|浏览量:

在实际应用中，我们经常会查看可执行文件（目标文件）的文件头信息、段表、节区表、符号表、重定位表、动态链接信息以及不同平台特有的信息。

假设存在以下测试程序：

查看 ELF 文件头信息

–file-header / -h 显示文件的文件头信息

上面的结果一般包含以下内容：

  1. 魔数Magic，这一行数据一般包括：7f 45 4c 46（表明是ELF文件）；02（ELF64）；01（小端模式）；01（ELF 当前版本）
  2. Data数据这一行表明：当前的数据是小端模式
  3. Type 为 DYN 表示共享目标格式，也可能是位置无关可执行文件（PIE），需要结合其他字段判断。
  4. Entry point address：表明这个可执行文件的入口地址，一般就是 _start 函数的地址
  5. Start of这些数据表明该文件的节头表、程序头表在文件中的起始偏移位置
  6. 后续的信息

表明，这个可执行文件的文件头大小信息、节头表的个数以及每一个节头表的大小；程序头表的个数以及每一个程序头表的大小等信息。

上表对应的 ELF 文件视图如下：

-l / –program-headers 程序头信息

这个结果是 ELF 文件中专门为装载器准备的一组段（segment）描述信息，它主要用于程序装载和运行时，由操作系统加载器和动态链接器使用。需要注意的是：上面的段segment和下面的segment map相对应，也就是说第三个段对应于下面的02。每一个segment包括以下内容：

  1. Type：段类型
  2. Offset：该段内容在文件中的起始偏移
  3. VirtAddr：装载到内存后的虚拟地址
  4. PhysAddr：物理地址（不需要关注）
  5. FileSiz：该段在文件中的大小
  6. MemSiz：该段装入内存后的大小
  7. Flg：这个段的权限
  8. Align：对齐要求

在上述结果中，存在11个segment（段），主要包括以下几种类型的段：

  1. PHDR：程序头表自身所在的位置，也就是通过命令 llvm-readelf -h 查找到的程序头表的开始地址；
  2. INTERP：程序需要的动态加载器路径（动态链接器路径），在这里是0x1c，也就是28，即/lib64/ld-linux-x86-64.so.2字符串的长度；
  3. LOAD：这4个LOAD段可以加载到内存中，在这里，有时候MemSiz > FileSiz，说明有一部分在文件中不占实际空间，在内存中需要分配；
  4. DYNAMIC：这个是动态段（.dynamic段）的信息，里面就是动态表信息（llvm-readelf --dynamic ./a.out）；
  5. NOTE：对应 note 信息，例如 ABI 标签。

-S / –section-headers 节区表信息

这个文件是可执行文件的节区表信息，这些信息可以表明每一个节区的起始位置、大小以及其他信息。

查看文件的 动态/重定位 信息

–dyn-relocations 展示动态重定位条目信息

通过 --dyn-relocations 参数，可以确定文件中的动态重定位条目。
这些条目可供动态链接器在程序装载或运行时使用，可以用于修正可执行文件中的尚未确定的地址引用。

通过上述的输出，该可执行文件中存在两个动态重定位节区：RELA重定位节、PLT重定位节。这些节区分别保存了不同类型的动态重定位信息。如：

  1. RELA 重定位节：主要保存一般动态数据引用、全局变量、相对地址等重定位
  2. PLT 重定位节：主要保存外部函数调用相关的重定位

每一行有以下信息：

  1. Offset：需要被修正的位置，即重定位结果将写入的地址
  2. Info：编码后的重定位信息，通常包含符号索引和重定位类型
  3. Type：重定位类型，决定该重定位项的计算方式
  4. Symbol’s Value：关联符号的值
  5. Symbol’s Name + Addend：关联符号名以及加数

-r / –relocs / –relocations 展示重定位条目

-r 查看文件的重定位节，--dyn-relocations 按动态链接信息查看动态重定位。本例的可执行文件中，两者展示相同的动态重定位条目，沿用上一节的输出；可重定位目标文件通常还包含等待静态链接器处理的条目。

符号表相关

-s / –syms / –symbols 输出符号表信息

这个展示的文件的所有符号信息，每一行包含以下内容：

  1. Value：符号值，通常可以理解为符号对应的地址或偏移值。对于已定义的函数/变量，表示地址；对于UND符号，通常是0；
  2. Size：符号大小
  3. Type：该符号是什么符号，比如说该符号是一个函数符号
  4. Bind：符号绑定属性，表示这个符号在链接层面的绑定方式。比如说局部符号（LOCAL、只在当前目标文件内部有效）、全局符号（GLOBAL、可被外部引用）、弱符号（WEAK、优先级低于强符号）
  5. Vis：可见性，表示该符号对外部是否可见、可否被其他模块正常引用
  6. Ndx：该符号所在的节区索引，除此之外还有 UND（未定义符号）、ABS（绝对符号）
  7. Name：符号名

其中，.dynsym 主要用于动态链接，.symtab 则保存更完整的符号信息。

用法总结

常用场景

1. 排查链接错误

当程序在编译或链接时出现 undefined reference to xxx 等错误时，可以通过符号表查看：

  • 该符号是否为未定义符号（UND）
  • 当前文件中是否真的定义了该符号
  • 该符号是否应当由其他库提供

2. 确认新增代码是否真正进入二进制文件

在添加新的函数、全局变量或功能模块后，可以通过查看符号表确认：

  • 新写的函数是否已经出现在可执行文件或目标文件中
  • 新增变量是否生成了对应符号
  • 符号是否被优化掉、内联掉或隐藏了

3. 分析动态链接依赖

通过动态符号表 .dynsym，可以看到程序运行时需要哪些外部符号，例如：

  • strlen
  • __libc_start_main
  • std::cout

这有助于分析程序依赖了哪些动态库和运行时接口。

4. 辅助调试与反汇编分析

符号表可以帮助我们建立“地址”和“符号名”之间的对应关系，例如：

  • 某个地址对应哪个函数
  • 程序入口 _start 在哪里
  • main 函数的地址是多少

这在调试、反汇编和问题定位时很有帮助。

5. 查看符号可见性与导出情况

在库开发或二进制分析中，可以通过符号表查看：

  • 哪些符号是局部符号（LOCAL）
  • 哪些符号是全局符号（GLOBAL）
  • 哪些符号是弱符号（WEAK）
  • 哪些符号对外可见，哪些符号被隐藏（如 HIDDEN）

6. 用于二进制分析、逆向和性能分析

在以下场景中，符号表也经常使用：

  • 二进制分析
  • 逆向分析
  • 性能分析
  • crash 定位
  • 链接优化和布局优化

因为符号表能够把程序中的地址还原为更有意义的函数名或变量名。
